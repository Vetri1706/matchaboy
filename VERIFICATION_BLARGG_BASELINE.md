# Verification evidence

The final optimized C++20 executable passed all **20 selected original Blargg
ROMs**, including the aggregate CPU suite and instruction timing, and matched
the original **dmg-acid2 reference image pixel for pixel**. Unit and sanitizer
runs each passed **16 groups / 9,406,233 assertions**. No binary test ROM was
modified, replaced with a synthetic oracle, or special-cased by the CPU.

This establishes the tested CPU behavior, instruction/access timings and PPU
rendering cases. It does **not** establish complete DMG hardware cycle accuracy:
the specific remaining timing gaps are listed below.

## Unit, timing and fuzz coverage

- Exhaustive ADD, ADC, SUB, SBC and CP input combinations, including incoming
  carry states; independent result and carry/half-carry checks.
- All 2,048 A/N/H/C DAA inputs, plus decimal arithmetic oracles for every pair
  of valid two-digit BCD numbers under addition and subtraction.
- Signed SP offsets across register boundaries; all primary opcode byte
  values; all 256 CB opcodes; conditional taken/not-taken cycle penalties.
- EI delay and cancellation, EI/EI, interrupt priority and stack pushes,
  HALT wake and duplicated fetch, normal STOP clock gating and joypad wake.
- DIV/TAC falling edges, four-T-cycle timer overflow delay, reload write
  behavior, cancellation of a genuinely pending reload, and timer interrupts.
- Memory echo, unusable memory, complete serial shifting, DMA restrictions,
  first-cycle access, startup, restart and transfer completion.
- MBC1/MBC3 banks, RAM enable, RTC latch stability, halt, 512-day overflow
  and explicit carry clearing.
- PPU mode transitions, 456-dot lines, 4,560-dot VBlank, LY153 dot4, LCD-off
  state, backgrounds, window, sprite priorities, and 8x16 behavior via acid2.
- 1,760 PPU timing configurations: every SCX value; all 168 visible/partially
  visible sprite X positions at each fine-scroll phase; window WX=7..166.
  These check scalar stall rules separately from the external image test.
- Two million PPU dots with deterministic randomized MMIO, VRAM and OAM
  activity, seed 0x534D3833. State/access bounds are asserted each dot; the
  same workload runs under ASan/UBSan. This is memory/state-safety stress,
  not a golden rendering oracle for arbitrary mid-scanline changes.

## Debug and rerun history

The first external campaign passed the eleven individual CPU ROMs, aggregate
CPU ROM, instruction timing and six memory timing ROMs. The extra HALT test
reached its terminal self-loop but timed out after four billion T-cycles with
no readable verdict. Its [trace remains available](artifacts/rom-attempt-1/halt_bug.trace.txt).

The original HALT binary declares type 02 (MBC1+RAM) while its RAM-size byte is
zero. Its framework writes the signature, log and final status to A000. A
generic --ram-size option now allows explicit physical cartridge configuration;
the runner supplies --ram-size 8192 for this development-cartridge ROM. The
binary remains byte-identical, the override is recorded, and zero-size RAM
still means absent RAM by default. The [isolated rerun passed](artifacts/halt-attempt-2/summary.json).

Review also corrected DMA startup/restart: the first following M-cycle preserves
the previous bus owner and an existing transfer continues during restart
latency. This follows the hardware-tested
[Mooneye DMA startup case](https://github.com/Gekkio/mooneye-test-suite/blob/main/acceptance/oam_dma_start.s).
Other corrections mask sprite row addresses when height changes during a line
and limit STOP wake to selected joypad inputs. The expanded unit suite,
sanitizers, all 20 ROMs from scratch, and final framebuffer comparison passed
after those changes. No instruction flag or CPU timing defect was exposed by
the selected external CPU ROMs; no multi-attempt ALU repair history is claimed.

## Remaining accuracy and product limits

- Instruction/access M-cycle ordering and per-T-cycle peripherals are
  implemented. Sub-M-cycle analog bus behavior, every interrupt race and every
  hardware revision are not independently verified.
- DMG OAM corruption from 16-bit CPU bus operations and OAM/PPU bus conflicts
  during DMA are not implemented. DMA copies and CPU blocking are modeled,
  but the PPU observes the incrementally updated OAM array.
- LCD re-enable first-line quirks, WX<7/startup overlap, arbitrary midline window
  changes and exact object-fetch cancellation are incomplete or unverified.
  Some pathological window/sprite combinations exceed the usual 289-dot mode3
  bound here. Duration is not clamped at the cost of discarded pixels. Complete
  hardware accuracy requires further PPU timing ROMs and corresponding fixes.
- STOP models the normal DMG path. Obscure pending-input and oscillator startup
  behavior is not modeled. RTC advancement uses emulated time, not host wall
  time; offline advancement and its independent oscillator during STOP are
  not implemented. Battery-backed RAM/RTC persistence is not implemented.
- APU waveform generation/audio timing, CGB hardware, boot-ROM execution,
  unsupported cartridge controllers, save states and a graphical frontend are
  outside this implementation. Audio MMIO storage is present without an APU.

## Reproduce

```sh
cd dmg
python3 tools/fetch_roms.py
python3 tools/fetch_ppu_tests.py
python3 tools/verify.py --build-check --extra --output artifacts/new-rom-run
python3 tools/verify_ppu.py --output artifacts/new-ppu-run
```

Use fresh output directories. After compilation, running a supplied ROM needs
no Python, network, external test binaries or reference images.
