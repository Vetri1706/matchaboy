# Pixel pipeline verification

All **24 original DMG Mealybug images now match exactly**: 552,960 pixels,
zero differences. They passed together with 65 selected Mooneye tests, Blargg,
OAM, acid2, optimized units and ASan/UBSan in
[the final frozen campaign](artifacts/fifo-verification-6/summary.json).
The exact executable and matching source archive are retained beside that
report. [Every image, trace and pixel comparison](artifacts/fifo-verification-6/mealybug/summary.json)
is available for inspection.

The completion audit identified a specific missing digital behavior: disabling
the window during a scanline must finish the current tile, resume background
on a tile boundary, and permit a correctly positioned subsequent activation
to fetch the next window row. The previous permanent per-line activation latch
could not do this. Original Mealybug tests provide additional independent
pixel-level evidence for these operations.

## Original oracle

Original binaries and sources are pinned to the author's revision
[`70e88fb90b59d19dfbb9c3ac36c64105202bb1f4`](https://github.com/mattcurrie/mealybug-tearoom-tests/tree/70e88fb90b59d19dfbb9c3ac36c64105202bb1f4).
The binary archive SHA-256 is
`e2fa6ca96ad48bd64d7297fda042db04c15117a730da3bbd590f139e89b150bd`;
the source archive SHA-256 is
`c7f01ac036fed2bd94f515ac3d1c19924d8b57cf38db0db03ee909eef2712153`.

The archive contains 31 ROMs and 24 published DMG reference images. Seven ROMs
have references for CGB only and are explicitly excluded from the DMG image
campaign. The original source, MIT license, reference PNGs and physical-device
photos are all retained with immutable per-file SHA-256 inventories under
`roms/mealybug` and `roms/mealybug-source`.

The author states that the exact reference PNGs are produced by their emulator;
the repository's photos show the ROMs running on physical devices. These are
independently published references, not images generated by this implementation,
and are not described here as direct digital captures from physical hardware.
No expected pixel, test instruction or original timing constant is edited.

The capture protocol is an actually executed `LD B,B` software breakpoint.
This differs from Mooneye's Fibonacci-register verdict. The harness reports
`captured`, which is not a pass. The verifier requires that capture, a zero
process exit, a complete 160-by-144 framebuffer, and zero differing pixels
against the original DMG PNG. All files, traces, registers, commands, hashes
and mismatches are retained. Source, executable and oracle changes invalidate
the campaign.

## Baseline and iteration

[The preserved baseline](artifacts/mealybug-baseline/summary.json) matches 1/24
images. It uses the exact engine source from the passing Mooneye campaign plus
the new capture-only harness, compiled under `artifacts/mealybug-baseline-build`.
The baseline failures are evidence for further work, not excluded passing tests.

The final implementation corrects window activation and reactivation, WX edge
positions, palette transitions, map selection, independent bitplane sampling,
object fetch cancellation and size selection, and live scroll/control writes.
The generic post-boot logo and tile map are initialized in ordinary writable
VRAM for every cartridge; there is no special reference-image substitution.

The final window defect exposed seven omitted offscreen clocks at WX=0.
Fetching earlier and discarding seven actual window pixels preserves the
visible start time while allowing the next tile to latch before an LCDC write.
That change exposed an extra refill bubble when discarded pixels crossed a
tile boundary. Retiring the pixel before parallel-loading the FIFO fixed the
ordering for every discarded pixel. The fetch counter now holds only while the
FIFO is occupied, with no fixed sleep after a successful load.

[The retained architectural findings](artifacts/FINAL_PIPELINE_FINDINGS.md)
explain the original trace, rejected intermediate probe and primary hardware
references. The first LCD-clock sampling phase is explicitly identified as
an inference from circuit ordering and independent images. No expected image,
ROM instruction or test timing constant changed during these repairs.

## Reproduce

```sh
python3 tools/fetch_mealybug.py
make -j4
python3 tools/verify_mealybug.py --output artifacts/new-mealybug
```

For focused diagnosis, use `--windows` or `--only SUBSTRING`, and use `--binary`
to select a private diagnostic executable. Fresh output directories are required.
An alternate binary's recorded hash identifies what ran; its current source
inventory alone does not prove that the alternate executable was built from it.

## Mode 3 duration

The published 172–289-dot range conflicts with the same documentation's additive
penalties in some combined object/window scenes. The upstream
[Pan Docs issue 578](https://github.com/gbdev/pandocs/issues/578) tracks this:
172 base dots + 7 fine-scroll dots + ten 11-dot object fetches + 6 window dots
equals 295. A retained real-PPU diagnostic reproduces that geometry in
`artifacts/mode3-bound-audit`. The implementation does not clamp the duration
and silently discard pixels to satisfy an inconsistent bound. Exact disputed
cases require hardware evidence rather than an arbitrary numeric cap.
